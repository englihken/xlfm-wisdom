## 1. 改了什么

### 1.1 判级（A1、A2）

- `level-cues.ts`：`levelFromCues()` 先看「自述没开始」（没念过／还没开始／刚开始／不会念／零基础），命中就返回 `beginner`，并把被压下去的 experienced 线索留在 `hits` 里（`capped-experienced:清修` 这种），日志能看出来是压过的。原来只有 practising 被压，`清修` 之类的行话仍会把一个自称没开始的人抬成同修——A1 要的就是这一条。
- `care-pipeline.decideTurnLevel()`：`contacts.stage` 有值就直接用（**可以降级**，义工见过本人），没值才 `max(线索, 已持久化)`。`[level]` 日志的 `source=stage|cues|persisted` 照旧。
- 持久化仍是只升不降（migration 051 的口径没变）。

### 1.2 个案数字（A3）

- `care-pipeline`：`caseTexts` 由 `type==='case_qa'` 改为 `case_qa` ＋ `letter_qa`。《解答来信疑惑》从此和玄艺问答／综述一样——数字只能转述（「台长对某位同修开示…」），写成建议就判 `number_case_generalized`。通则性上限句（「不能超过 108 遍」）本来就走转述，不受影响。
- 提示词（同修轮）：「佛台请下／结缘／搬迁／换像：只转述与访客情形相同的原文；情形不同就说明『这是另一种情况』。张数一律请义工面谈，不把某一篇《解答来信疑惑》里某位同修的张数、遍数开成这位访客的功课。」
- R29 加断言：回复里不得有带数字的 📿 行，也不得出现「你可以念 N 张／遍」这类个人化写法。

### 1.3 同修轮第一轮（A7）

- 提示词加一条：第一轮结尾不要用是非问句（「有没有…？」），要问就问具体的、把话题带深的问题，或者不问。R28 第二轮反问的根源就在第一轮问了「有没有卡住的地方」。
- R28 断言按 (b) 拆：`firstTurnChecks` 放结构（≥2 段逐字引文、出处、无 📿、无遍数），第二轮只留无尾巴／无 📿／无遍数／不问有没有念经／判级 experienced。

### 2.1 R32 的真正原因：pinned 卡被检索到的旧副本顶掉了

四次都挂之后我停下来做了两个不调模型的测量：

1. **卡的文本本身没问题**：`docs/canon/pinned-cards.json` 里那段「张数的一般说法……4-10 张……」抽得出 `4张 / 10张 / 7张 / 21张`，配对是 `小房子=4张` 等；把这段当作唯一来源跑 `checkDraft`，四种写法**全部 0 violation**。
2. **真实检索里却没有这段**：按 R32 原话跑一次真实检索，`wisdom_15eb9282…` 确实在结果里，但它的 `张数段=false`、`pinned=false`——**这条是普通向量检索命中的 Pinecone 旧副本**（Ken 还没点「重同步」，那份副本停在 09-13、没有小房子一节），而 `withPinnedCanon()` 的去重是「ranked 里已有这个 id 就不再追加 pinned 版」，于是**权威副本被旧副本挤掉**。检索集合里 `4张 / 10张 / 7张` 一个都没有，护栏把模型写出来的「4-10 张」判成 `number_not_in_sources` 剥掉（run b 的 decision log 三条 number 违规就是它）。

所以前三次改提示词都无效——模型第 2 次其实**写出来了**，是被护栏剥掉的；剩下的两次它学乖了，直接转介。

**修法**（`vector-search.withPinnedCanon`）：pinned 副本优先——同 id 时丢掉 ranked 里的那条，保留 pinned 的。这条 bug 不只影响 R32：**任何一次改卡之后，只要 Pinecone 副本还旧，生产上读到的就是旧文本**（生产的 pinned 来自库，是新的，但同 id 的旧副本会把它顶掉）。Ken 点「重同步」能修数据，代码这一侧也不该再依赖它。

**修完的检索侧复测**（不调模型，按 R32 原话跑真实检索）：卡这次是 pinned 那一份进来的——`张数段=true`、`pinned=true`；检索集合里 `4张 / 10张 / 7张` 都在；把那句一般说法当草稿跑 `checkDraft` → **0 violation**。也就是说模型现在写这句话不会再被剥掉。

## 3. 待架构师
