# 回复模型切换：Opus 5 → Sonnet 4.6（2026-09-11）

架构师决定（Ken 已委托）。依据 `docs/reviews/2026-09-11-batch-4.md` §8。

## 为什么切

同一套 R1–R21 + 18 chips + N1–N9，同一份 v2 提示词：

| | v2 Opus 5 | v2 Sonnet 4.6 |
|---|---|---|
| checks | 201/205 | 203/205 |
| 例全绿 | 38/41（护栏修后 R14/R18/R10 复跑全过） | 39/41 |
| 没过 | 低档波动 + 护栏（已修） | R4 引用漏节目日期（格式项）、R19 checker 假阴性（已修） |
| 每轮 p50 / p90 | 28.0 s / 49.7 s | 18.9 s / 30.2 s |
| 首字 | 8.7 s | 2.9 s |
| 每轮成本 | $0.189 | $0.125 |

batch 1 时 Sonnet 输在实质（R14 漏《解结咒》、R13 三大支柱不全、R6 丢引用）——那是提示词自相矛盾，模型挑错边。F08 合并后这三例 Sonnet 全过，R18 首跑 6/6。剩下的 R4 是「引了对的来源、少写一个日期」，Opus 在 v2 首跑也丢过一次（R6），是两种模型都有的措辞波动，用检查＋重试兜，不用靠模型。

访客感受：首字 8.7 s → 2.9 s，整轮 28 s → 19 s。这就是 Ken 说的「以前很快、现在越来越慢」要回去的地方。

## 怎么切（CC）

1. `REPLY_MODEL` 默认 → `claude-sonnet-4-6`（v2 提示词、overlay）。Opus 保留为一行环境变量回退：`REPLY_MODEL=claude-opus-5`。
2. **按档覆盖**（小改，现在就加）：`REPLY_MODEL_HIGH`（缺省＝`REPLY_MODEL`）。观察期若只有 high 档露怯，就只把 high 档指回 Opus，不整体回退。
3. **引用格式软检查**：回复引用了网站问答类来源（解答来信／玄艺问答／玄艺综述／玄学问答／精彩节目摘录）却没带日期（「开示于…」或节目日期）→ 像护栏那样带提示重试一次；重试仍缺就放行、打 `citation_no_date` 标记进 review 记录，**不 strip、不加尾巴**。R4 用这个兜。
4. R19 checker 已认「× N」→ 切完后 Sonnet 全套再跑一次收口（R4、R19 应绿），数字贴进 batch 4 报告 §8 下面。
5. 部署后 chips 不用手动预热——今晚 00:30 刷新会全部换成 Sonnet 生成；**明早看 18 条**（zh/en/id 各 6）：有没有 blanket 尾巴、遍数齐不齐、字数（入门轮 ≤ 400 字正文）。有问题的那条单独重生成。

## 观察期 48 小时 — 回退线写死

每天一份 `docs/reviews/2026-09-12-sonnet-watch.md`、`…-09-13-…`（`measure-latency.ts` + `conversation_reviews` + `failed_replies`）：

| 指标 | 怎么算 | 回退线 |
|---|---|---|
| 首轮首字 / p50（按 low/medium/high 三档分开） | 生产日志 | 首轮 p50 > 15 s 连续两天 → 查原因（不一定是模型） |
| 审核 c/d/e/f 未过率 | Sonnet 当天 vs 切换前 7 天 Opus 基线（CC 先把基线算出来写在 09-12 的报告顶上） | 高于基线 1.5 倍 → 先按档回退（第 2 条），再报架构师 |
| 护栏 strip 率 / blanket 尾巴数 | `[verbatim-guard]` 日志 | strip > 15% 或尾巴明显增多 → 报架构师 |
| **任何一条**过了护栏但数字无据、或门槛说错（「先念两周」「要会四部经」） | 人工审 | **立即整体回退**，贴对话 |
| 未回复 / 队列 | `failed_replies` | 与切换前持平；变差先查 quota |

架构师 24 小时后读 30 条生产对话（与切换前一周同类问题并排），在 Project 记结论。
