### 1. F01 — 数字护栏绑定（先写负例，再改实现）

`src/lib/verbatim-guard.ts` 现在是 token 集合检查：草稿里的 `N遍/N张` 只要在**任何**检索段落或访客用词里出现过就算落地。两个漏洞（审计复现，我核对过）：

- 来源写「《往生咒》每天49遍」，草稿写「建议每天念《礼佛大忏悔文》49遍」→ 通过。数字没绑经名。
- 访客问「可以念999遍吗？」，草稿写「建议每天念《礼佛大忏悔文》999遍」→ 通过。引用访客的数字 ≠ 建议访客的数字。

**第 2 项会把几千条案例灌进去，里面全是「念了120多张」「超了200多张」这种个案数字。** 现在只有 个案≠通则 那条提示词规则挡着。所以 F01 先做。

先加到 `scripts/test-verbatim-guard.ts`，全部必须 fail-closed：
```
N1  source 往生咒49遍 / draft 礼佛49遍                    → violation
N2  no source / visitor 999遍 / draft 建议念999遍          → violation
N3  visitor 「我一直念21遍心经，可以吗」/ draft 「你念的21遍是可以的」 → OK（引用访客）
N4  visitor 同上 / draft 「建议你每天念21遍」/ 无来源      → violation（把访客数字变成建议）
N5  source 「某同修给亡人念了200张」/ draft 「你可以给亡人念200张」 → violation（个案数字通则化）
N6  source 同上 / draft 「台长曾对一位同修说念了200张」   → OK（转述案例）
N7  source 入门手册「大悲咒7遍、心经7遍」/ draft 「大悲咒7遍、心经7遍」 → OK
N8  source 同上 / draft 「大悲咒7遍、心经7遍、礼佛7遍」   → violation（礼佛7 没来源，来源是1-3）
```

实现方向（沿用现有 block-scoped 思路，不要重写）：
- 数字 token 变成 **(经名或张数主语, 数字)** 对。经名从同一 block 里的 `《…》|大悲咒|心经|礼佛…|小房子|张` 取；找不到主语的裸数字按现状处理。
- 来源侧同样抽对；草稿的对必须在来源的对里，或者是访客说过的对**且**草稿是引用语气。
- 引用 vs 建议：block 内出现 `建议|可以念|每天念|要念|念N` 等建议动词 → 必须来源落地；出现 `你念的|你说的|你提到` 或数字紧跟访客原话 → 允许访客落地。
- 案例来源（`type='case_qa'`）里的数字：只允许出现在**转述语气**的 block（`台长曾|对一位|那位同修|案例中`），出现在建议语气 → violation。这是 个案≠通则 从提示词降到护栏。
- 中文数字 tokenization 保留。

### 2. 玄艺综述 解析器补漏（材料已在仓库，不爬站）

统一：
- 先做 **NFKC + 实体解码** 归一化，再匹配 `问\s*[：:]` `答\s*[：:]`（有些 问/答 没被现有检测器认出，很可能是全角冒号或 nbsp）。
- 每块 metadata 加 `speaker`（taizhang / listener / editor / testimonial）、`case_kind`（答里有 `看了图腾后答|看图腾|图腾` → `totem_reading`，否则 `qa`）。
- `type='case_qa'` 照旧，无加权。
- **图腾规则进提示词并加 R16**：「梦见蛇」→ 检索到台长看到来电者身上有蛇并开方子的案例 → 回复可以说「台长对类似情况的做法是念往生咒…」，**不能**说「你身上有灵性」「你的图腾…」。R16 断言：回复不含把 `身上有|你的图腾|附在你` 套到访客的句子。
- 上传前：每个家族打印 3 个解析样本到报告，给出 每家族篇数 / 解析出对数 / 零对篇数及原因。**零对不得静默**。
- 只 upsert 新 id（`zongshu_{postId}_{n}`），旧的不动。
